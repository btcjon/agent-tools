# Hermes bridge vs native hint acceptance check (2026-09-25)

Source: [20 allowlisted result rows](hermes-bridge-native-ab-2026-09-25.jsonl), generated by [the reusable read-only runner](../scripts/hermes_native_hint_eval.py). Five fixed Notion tasks were run twice in fresh `gpt-6-sol` CLI sessions, with bridge/native arm order reversed on repeat two. Direct read-only Notion MCP checks established the answer key immediately beforehand. The runner never saved prompts, page bodies, raw tool arguments, credentials, or transcripts. Its original audit checked deferred Notion tool names; Astra identified that direct calls were missing, so the runner was repaired afterward to reject unexpected direct and deferred tools and mismatched arm/model/capability/session metadata. This is **post-execution detection, not write prevention**. No gateway config/restart was part of the test.

Bridge used 123,311 fewer counted tokens (~11.7% relative to native) on this sample, but token totals include cache reads and are not direct billing or initial-context measurements. Wall-clock difference is negligible at this sample size. On both search repeats, native invoked an extra `notion-fetch` after `notion-search`; bridge used `notion-get-tool-access` plus `notion-search` only. Bridge's selected cards were sufficient for Hermes to find native `list-favorite-pages` and `get-teams` without a model-facing name hint. For a page fetch, bridge used its receipt-bound `mcp__jev_skill_advisor__notion_fetch` and native used `mcp__notion__notion_fetch`.

A post-hoc direct-tool-name audit found `terminal` in three heading-count sessions (bridge repeat 1, native repeat 1, bridge repeat 2), in addition to the recorded Notion fetches. The terminal commands were not saved in this evidence and were not part of the original allowlist audit. They mean the stronger claim "zero writes of any kind" is **not proven** for the historical runs. The repaired runner now stops on such a call and would require a different fixed prompt or separate reviewed read-only terminal policy before reuse on that task. The remaining 17 sessions used only the expected tool wrapper and read-only Notion/bridge targets by name.

Decision: keep the existing **bridge default** and the native hint **opt-in**. The native experiment showed no quality or efficiency advantage over the actual default. This does not rule out native hints on another harness or task distribution. No production promotion, Notion mutation, native-tool hiding, or symlink retirement follows from this result.
